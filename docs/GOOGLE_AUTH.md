# Вход через Google и «Забыли пароль?» — включение и ручная проверка

Код входа через Google и восстановления пароля уже в проекте. Автотесты проверяют его без настоящего Google:

| Что | Где | Как |
|---|---|---|
| Логика после входа (профиль, выход при сбое, тексты ошибок) | `tests/googleAuth.test.js` (`npm test`) | подставной Firebase |
| Вход через Google, повторный вход, тот же UID, нет дублей, сброс пароля | `tests-emulator/authFlows.emulator.js` (`npm run test:rules`) | эмулятор Auth, `signInWithCredential` |
| Кнопка, форма «Забыли пароль?», языки, 320px | `tests-e2e/admins.e2e.mjs` (`npm run test:e2e`) | эмулятор Auth + Chrome, окно Google не открывается |

Настоящее окно Google автотесты не открывают. После включения Google в Firebase Console проверьте вход вручную по списку ниже.

## 1. Настройка Firebase Console (делает владелец проекта)

1. Firebase Console → проект магазина → **Authentication → Sign-in method**.
2. **Google → Enable**. Укажите **Project support email** (адрес, который пользователи увидят в окне Google). Сохраните.
3. **Email/Password** должен остаться включённым: на нём работают вход по паролю и «Забыли пароль?».
4. **Authentication → Settings → Authorized domains**: должны быть `localhost` и домен сайта на Vercel
   (например `aroma-donna.vercel.app` и свой домен, если он есть). Без домена в списке Google вернёт
   `auth/unauthorized-domain`, а сайт покажет понятное сообщение.
5. Необязательно: **Authentication → Templates → Password reset** — язык и текст письма для смены пароля.

Firestore Rules для этого менять не нужно: профиль `users/{uid}` создаётся по тем же правилам, что и при регистрации по паролю.
Переменные окружения Vercel менять не нужно.

## 2. Ручная проверка входа через Google

Проверяйте в обычном окне браузера (не в режиме разработчика с эмуляторами), с телефона и с компьютера.

| № | Действие | Ожидается |
|---|---|---|
| 1 | `/register` → «Продолжить с Google» → аккаунт Google, которого в магазине ещё нет | Переход в личный кабинет. В Firebase Console → Authentication появился один пользователь с провайдером Google. В Firestore → `users/{uid}` — `name`, `email`, `createdAt` |
| 2 | Выйти → `/login` → «Продолжить с Google» → тот же аккаунт | Тот же UID, второго пользователя нет, `createdAt` профиля не изменился |
| 3 | Открыть окно Google и закрыть его, не выбрав аккаунт | Остаётесь на странице входа, ошибки нет, кнопку можно нажать снова |
| 4 | Заблокировать всплывающие окна для сайта и нажать кнопку | Сообщение «браузер заблокировал окно» на текущем языке |
| 5 | Повторить шаг 1 на ru, ky, en; светлая и тёмная тема; ширина телефона | Тексты переведены, ничего не выходит за экран |
| 6 | Войти через Google, открыть `/login` | Сразу личный кабинет |
| 7 | Оформить заказ после входа через Google, выйти и войти снова | Заказ виден в кабинете (тот же UID) |

## 3. Аккаунт с паролем и тот же e-mail в Google

Firebase хранит один аккаунт на один e-mail (настройка по умолчанию). Проверено на эмуляторе:

- Покупатель зарегистрирован по паролю, затем входит через Google с тем же адресом → **тот же UID**,
  профиль и заказы сохраняются, второго пользователя нет. Firebase при этом убирает вход по паролю,
  если адрес не был подтверждён (Google считается более надёжным подтверждением адреса).
- Чтобы вернуть вход по паролю: «Забыли пароль?» на странице входа → письмо → новый пароль.
  UID тот же; после этого работают оба способа — и пароль, и Google.

Автоматического объединения аккаунтов в коде нет: сайт не связывает аккаунты сам и не создаёт второй аккаунт.

Ручная проверка: зарегистрироваться по паролю на свой Gmail-адрес → выйти → войти через Google →
в Console тот же UID → выйти → «Забыли пароль?» → письмо → новый пароль → вход по паролю работает → вход через Google работает.

## 4. Ручная проверка «Забыли пароль?»

| № | Действие | Ожидается |
|---|---|---|
| 1 | `/login` → ввести e-mail → «Забыли пароль?» | Открылась форма, e-mail уже подставлен |
| 2 | Ввести неверный адрес | Ошибка у поля, письмо не отправлено |
| 3 | Ввести адрес существующего аккаунта | «Проверьте почту», письмо пришло (проверьте «Спам») |
| 4 | Ввести адрес, которого нет | Тот же ответ «Проверьте почту», письма нет (по форме нельзя узнать, есть ли аккаунт) |
| 5 | Перейти по ссылке из письма, задать новый пароль, войти | Вход работает, UID, профиль и заказы те же |

## 5. Если что-то не работает

| Сообщение на сайте | Причина | Что сделать |
|---|---|---|
| Вход через Google не включён | `auth/operation-not-allowed` | Шаг 1.2 |
| Домен сайта не разрешён | `auth/unauthorized-domain` | Шаг 1.4 |
| Не удалось сохранить профиль | Профиль `users/{uid}` не записан (правила, сеть) | Пользователь выходит из аккаунта автоматически; проверить сеть и опубликованные правила |
| Аккаунт с этим e-mail уже существует | `auth/account-exists-with-different-credential` (только если в Console включено «несколько аккаунтов на один e-mail» или другой провайдер) | Войти прежним способом |
