# AROMA DONNA — интернет-магазин премиальной парфюмерии

Учебный проект: полноценный интернет-магазин женской и мужской парфюмерии на **React + Vite**.
Каталог с поиском и фильтрами, корзина, избранное, демо-промокоды, оформление заказа,
регистрация и личный кабинет, тест подбора аромата, **3 языка** (русский, кыргызский, английский),
**светлая и тёмная темы**, адаптивная вёрстка. Валюта — **кыргызский сом (KGS)**.

> ⚠️ **Это демонстрационный проект.** Бренды, товары, рейтинги, наличие, адреса и телефоны вымышлены.
> Реальные заказы и оплата не принимаются, деньги не списываются. Это честно указано и в самом интерфейсе.

## 1. Инструкция для запуска на MacBook (пошагово)

### Что нужно установить один раз

- **Node.js** версии 20 или новее (LTS) — скачайте с сайта [nodejs.org](https://nodejs.org) установщик для macOS и установите.
  Проверка в Терминале: `node -v` (должно показать `v20...` или выше) и `npm -v`.
- **Visual Studio Code** — [code.visualstudio.com](https://code.visualstudio.com).

### Шаг 1. Скачать архив

Скачайте файл **`Aroma-Donna.zip`** из чата (кнопка скачивания на карточке файла).
Обычно он попадает в папку **«Загрузки» (Downloads)**.

### Шаг 2. Распаковать

Дважды щёлкните по `Aroma-Donna.zip` в Finder — рядом появится папка **`Aroma-Donna`**.
Удобно перенести её, например, на Рабочий стол или в папку «Документы».

### Шаг 3. Открыть папку в VS Code

Откройте VS Code → меню **File → Open Folder…** (Файл → Открыть папку) → выберите папку `Aroma-Donna` → **Open**.
Если VS Code спросит «Do you trust the authors?» — нажмите **Yes, I trust the authors**.

### Шаг 4. Открыть терминал в папке проекта

В VS Code: меню **Terminal → New Terminal** (или сочетание клавиш <kbd>Ctrl</kbd> + <kbd>`</kbd>).
Внизу откроется терминал, уже находящийся в папке проекта.
Проверьте командой `ls` — в списке должны быть `package.json`, `src`, `README.md`.

### Шаг 5. Установить зависимости

```bash
npm install
```

Команда скачает библиотеки (React, Redux Toolkit и др.) в папку `node_modules` и создаст файл
`package-lock.json`. Это займёт 1–3 минуты и требует интернета.

> В архиве есть `package-lock.json` (создан 28.10.2026 при проверке формы «Контакты»), поэтому установятся те же версии библиотек.
> После первой установки файл появится, и в дальнейшем можно использовать `npm ci` — он ставит точно те же версии.

### Шаг 6. Запустить проект

```bash
npm run dev
```

### Шаг 7. Открыть сайт в браузере

В терминале появится строка вида:

```
  ➜  Local:   http://localhost:5173/
```

Браузер откроется автоматически. Если нет — нажмите <kbd>Cmd</kbd> и щёлкните по ссылке, или вручную откройте
**http://localhost:5173** в Safari/Chrome.

### Шаг 8. Как понять, что всё работает

- В терминале нет красных сообщений `error`, есть строка `VITE ... ready in ... ms`.
- В браузере открылась главная страница с надписью **«Аромат, который говорит за вас»** и флаконами.
- В каталоге видны 24 аромата; кнопка «В корзину» увеличивает число на значке корзины.

Остановить сервер: в терминале нажмите <kbd>Ctrl</kbd> + <kbd>C</kbd>.

### Шаг 9. Если возникла ошибка

| Сообщение | Что сделать |
|---|---|
| `command not found: npm` или `node` | Node.js не установлен. Установите с nodejs.org и **перезапустите VS Code**. |
| `npm ERR! code ENOTFOUND` / `ETIMEDOUT` | Нет интернета или его блокирует сеть. Проверьте подключение и повторите `npm install`. |
| `npm ERR! code EACCES` (нет прав) | Не используйте `sudo`. Убедитесь, что папка проекта лежит в вашей домашней папке (Рабочий стол/Документы). |
| `npm ERR! ERESOLVE` (конфликт версий) | Выполните `npm install --legacy-peer-deps`. |
| `Port 5173 is in use` | Vite сам выберет другой порт (5174) — откройте адрес, который он напечатал. |
| Ошибки после неудачной установки | Удалите `node_modules` и `package-lock.json` и снова выполните `npm install`. |
| Белый экран в браузере | Откройте консоль разработчика (<kbd>Cmd</kbd>+<kbd>Option</kbd>+<kbd>I</kbd> → Console) и прочитайте красную ошибку. |

### Шаг 10. Дополнительные настройки для Firebase (необязательно)

Без Firebase магазин **полностью работает в демо-режиме**. Чтобы включить настоящую регистрацию и
сохранение заказов в облаке — см. [раздел 8](#8-демо-режим-и-firebase).

### Все команды

| Команда | Что делает |
|---|---|
| `npm install` | Устанавливает зависимости |
| `npm run dev` | Запускает сайт для разработки на http://localhost:5173 |

## 2. Технологии

| Технология | Зачем используется |
|---|---|
| **HTML5** (семантическая разметка: `header`, `nav`, `main`, `footer`, `section`, `article`) | Структура страниц, доступность |
| **CSS3** (CSS-переменные, Grid, Flexbox, media queries, анимации) | Оформление, адаптивность, светлая/тёмная тема |
| **JavaScript (ES2022)** | Логика приложения (TypeScript не используется) |
| **React 19** | Интерфейс из компонентов |
| **Vite** | Быстрый сервер разработки и сборка |
| **React Router** | Переходы между страницами без перезагрузки |
| **Redux Toolkit + React Redux** | Общее состояние: корзина, избранное, товары, пользователь, уведомления |
| **i18next + react-i18next** | Три языка интерфейса |
| **Firebase** (Authentication + Firestore) | Регистрация, вход, заказы — подключается через `.env`; без него работает демо-режим |
| **EmailJS** (`@emailjs/browser`) | Отправка формы «Контакты» на e-mail |
| **Vercel Functions** (`api/contact.js`) | Серверная отправка формы в Telegram — токен бота не попадает в браузер |
| **ESLint** | Проверка качества кода |

**Почему без Tailwind и Bootstrap.** Используется одна система стилизации — обычный CSS с
CSS-переменными. Так проще переключать темы (меняются только значения переменных) и проще
объяснить код: все стили лежат в 5 файлах папки `src/styles`.

**Изображения.** Флаконы — локальные SVG-иллюстрации в `public/images/products` (не зависят от
внешних сайтов). Если картинка не загрузится, компонент `ProductImage` покажет заглушку `placeholder.svg`.

## 3. Основные функции

**Каталог:** поиск по названию и бренду (с подсказками в шапке), фильтры по категории, семейству ароматов,
бренду, концентрации, цене и наличию, 6 видов сортировки, счётчик найденных товаров, сообщение
«ничего не найдено», сброс фильтров. Фильтры хранятся в адресной строке (`/catalog?family=floral&sort=priceAsc`).

**Товар:** галерея (3 вида), бренд, название, цена, выбор объёма 30/50/100 мл (у каждого своя цена),
концентрация, семейство, интенсивность, наличие, описание, пирамида нот, выбор количества,
«В корзину», «В избранное», блок похожих ароматов.

**Корзина:** добавление, удаление, +/− количество (1–10), стоимость позиции, общая сумма, значок с количеством
в шапке, очистка, сохранение после перезагрузки, сообщение о пустой корзине.

**Избранное:** добавление/удаление «сердечком», отдельная страница, сохранение после перезагрузки,
одинаковое состояние кнопки во всех местах.

**Демо-промокоды:** `AROMA10` (−10%), `DONNA500` (−500 KGS при сумме от 5 000), `WELCOME15`
(−15% от 3 000, одноразовый). Сообщения: пустое поле, неверный код, уже применён, уже использован,
не хватает суммы.

**Оформление заказа:** контакты, доставка (курьер / самовывоз / регионы), адрес, комментарий,
оплата **только при получении**, проверка всех полей, защита от двойной отправки, страница успеха.

**Аккаунт:** регистрация и вход с проверкой полей, защищённый личный кабинет, профиль, история заказов, выход.

**Тест подбора аромата:** 5 шагов, индикатор прогресса, «Назад», проверка ответов, результаты
с процентом совпадения и причинами, переход к товару, «Пройти заново».

**Прочее:** 3 языка с сохранением выбора, светлая/тёмная тема (учитывает настройку системы),
всплывающие уведомления, страницы «О магазине», «Контакты» с формой, «Доставка и оплата», FAQ, 404.

## 5. Структура проекта

```
Aroma-Donna/
├── index.html              # HTML-шаблон; скрипт ставит тему ДО загрузки React (без «мигания»)
├── package.json            # зависимости и команды
├── vite.config.js          # настройки Vite
├── eslint.config.js        # правила ESLint
├── vercel.json             # настройка маршрутов для публикации на Vercel
├── firestore.rules         # правила безопасности базы Firestore
├── .env.example            # образец переменных окружения (Firebase, EmailJS, Telegram)
├── api/
│   ├── contact.js          # Vercel Function POST /api/contact — отправка в Telegram
│   └── _lib/contactHandler.js  # её логика: проверка, лимит запросов, вызов Telegram Bot API
├── tests/                  # тесты (npm test)
├── tests-emulator/         # тесты firestore.rules на Firebase Emulator (npm run test:rules)
├── public/
│   ├── favicon.svg
│   └── images/products/    # 24 SVG-флакона + placeholder.svg (заглушка)
└── src/
    ├── main.jsx            # точка входа: подключает React к странице, провайдеры
    ├── App.jsx             # маршруты; загрузка товаров и пользователя при старте
    ├── i18n.js             # настройка трёх языков
    ├── layouts/            # MainLayout — общий каркас страниц (шапка + Outlet + подвал)
    ├── pages/              # 15 страниц
    ├── components/
    │   ├── common/         # общие: иконки, поиск, язык, тема, уведомления, поле формы…
    │   ├── layout/         # шапка, логотип, меню, мобильное меню, подвал
    │   ├── home/           # блоки главной страницы
    │   ├── products/       # карточки, фильтры, сортировка, страница товара
    │   ├── cart/           # корзина, итог, промокод, список избранного
    │   ├── forms/          # вход, регистрация, оформление заказа, обратная связь
    │   ├── reviews/        # отзывы: карточка, список, форма, выбор звёзд
    │   ├── account/        # профиль и история заказов
    │   ├── quiz/           # тест подбора аромата
    │   └── info/           # FAQ-аккордеон
    ├── features/           # Redux-слайсы: cart, favorites, products, user, notifications
    ├── store/store.js      # создание Redux-хранилища + сохранение в localStorage
    ├── services/           # «общение с внешним миром»: Firebase, авторизация, заказы, API товаров, форма связи
    ├── hooks/              # собственные хуки: тема, фильтры каталога, действия магазина…
    ├── utils/              # чистые функции: цены, проверка форм, фильтры, промокоды, подбор
    ├── data/               # демо-данные: товары, промокоды, вопросы теста
    ├── locales/ru|ky|en/   # переводы (translation.json)
    └── styles/             # variables.css (цвета тем), base, layout, components, pages
```

**Принцип разделения:** компоненты отвечают за внешний вид, `features/` — за общее состояние,
`services/` — за Firebase и хранение, `utils/` — за вычисления, `data/` — за данные.

## 6. React-компоненты

Всего: **58 компонентов интерфейса** в `src/components`, **15 страниц**, макет `MainLayout`,
корневой `App` и `ThemeProvider` (в `hooks/useTheme.jsx`). Вспомогательный `NotificationItem`
находится внутри `Notification.jsx`.

| `Icon` | Набор SVG-иконок без сторонних библиотек | Повсюду |

## 8. Демо-режим и Firebase

### Как приложение выбирает режим

`src/services/firebase.js` проверяет переменные `VITE_FIREBASE_*`. Если они **пустые** →
режим `demo`; если заполнены → режим `firebase`. Текущий режим показан в личном кабинете.

### Что работает в демо-режиме (без настройки)

| Функция | Как работает |
|---|---|
| Каталог, корзина, избранное, промокоды, квиз, языки, темы | Полностью, данные в `localStorage` |
| Регистрация | Сохраняет **только имя и e-mail** в `localStorage`. **Пароль не сохраняется и не проверяется** — это демонстрация интерфейса, о чём написано на странице |
| Вход | По e-mail, ранее зарегистрированному в этом же браузере |
| Заказы | Сохраняются только в этом браузере, помечены «Демо-заказ», в магазин не отправляются |
| Отзывы покупателей | **Не работают без Firebase**: показывается «Отзывы временно недоступны». Выдуманных демо-отзывов нет |
| Форма обратной связи | Работает после настройки EmailJS и Telegram ([раздел 9](#9-форма-контакты-emailjs-и-telegram)). Без настройки показывает ошибку «Отправка недоступна» — ложного «Спасибо» нет |

### Что даёт Firebase

Настоящая регистрация и вход (пароли хранит и проверяет Firebase Authentication),
профиль в `users/{uid}` и заказы в `users/{uid}/orders` в базе Firestore,
отзывы покупателей в коллекции `reviews`.

### Как подключить Firebase

1. Зайдите на [console.firebase.google.com](https://console.firebase.google.com) → **Add project** → создайте проект.
2. **Build → Authentication → Get started → Sign-in method → Email/Password → Enable.**
3. **Build → Firestore Database → Create database** (режим production, регион поближе, например `europe-west`).
4. Вкладка **Rules** в Firestore → вставьте **всё** содержимое файла `firestore.rules` из проекта → **Publish**.
   (Если правила уже публиковались раньше — опубликуйте заново: в них добавлен блок для отзывов.)
5. **Project settings (⚙️) → Your apps → значок `</>` (Web)** → зарегистрируйте приложение → скопируйте значения `firebaseConfig`.
6. В папке проекта скопируйте файл: `cp .env.example .env` и вставьте значения:
   ```
   VITE_FIREBASE_API_KEY=...
   VITE_FIREBASE_AUTH_DOMAIN=...
   VITE_FIREBASE_PROJECT_ID=...
   VITE_FIREBASE_STORAGE_BUCKET=...
   VITE_FIREBASE_MESSAGING_SENDER_ID=...
   VITE_FIREBASE_APP_ID=...
   ```
7. Остановите сервер (<kbd>Ctrl</kbd>+<kbd>C</kbd>) и снова запустите `npm run dev`.

### Отзывы покупателей (Firestore)

Страница `/reviews` и блок на главной показывают **только настоящие одобренные отзывы** (`status: 'approved'`)
из коллекции `reviews`. Новый отзыв уходит на модерацию (`status: 'pending'`) и появляется после одобрения.
Пока отзывов нет — показывается приглашение оставить первый.

**Как устроено:**

| Файл | Что делает |
|---|---|
| `src/services/reviewsStore.js` | Запросы к Firestore: одобренные отзывы (новые сверху, по 9 штук, «Показать ещё»), число и средняя оценка только по одобренным (`getAggregateFromServer`), новый отзыв со статусом `pending` |
| `src/services/reviewsService.js` | Подключение Firebase, понятные ошибки, «не чаще одного отзыва в минуту» |
| `src/hooks/useReviews.js` | Состояния загрузки, ошибки, пустого списка; отправленный отзыв в список не добавляется — он ждёт модерации |
| `src/components/reviews/*` | Карточка, список, форма, выбор звёзд |
| `src/utils/validation.js` → `validateReview` | Проверка в браузере: имя 2–50 символов, оценка — целое 1–5, текст 10–1000 символов |
| `firestore.rules` → `match /reviews/{reviewId}` | **Та же проверка на сервере Firebase** и права модерации |
| `tests-emulator/firestore.rules.emulator.js` | Тесты правил на локальном Firebase Emulator (`npm run test:rules`) |
| `src/pages/admin/AdminReviewsPage.jsx` и др. | Раздел модерации «Отзывы» в админ-панели (`/admin/reviews`) — `docs/ADMIN_SETUP.md`, раздел 11 |

Документ отзыва: `{ name, rating, text, lang, status, createdAt }`. Дату ставит сервер (`serverTimestamp()`),
новый отзыв всегда `status: 'pending'`; при модерации добавляется `moderatedAt` (см. `docs/ADMIN_SETUP.md`, разделы 8–11).
E-mail и другие личные данные не собираются — имя публикуется, о чём сказано под полем.

**Правила доступа к отзывам** (`firestore.rules`, модерация — этап D):

```
match /reviews/{reviewId} {
  allow read: if isAdmin() || resource.data.status == 'approved';     // посетитель — только одобренные
  allow create: if isValidReview(request.resource.data);              // любой, без входа; только 'pending'
  allow update: if isAdmin() && isValidReviewModeration();            // только status и moderatedAt
  allow delete: if isAdmin() && resource.data.status == 'rejected';   // только отклонённые
}
```

| Кто | Читать | Создать | Изменить | Удалить |
|---|---|---|---|---|
| Гость, покупатель, анонимный вход | только `approved` (и по ID) | да, только `status: 'pending'` | нет | нет |
| Администратор (`admins/{uid}`) | все статусы | да, только `status: 'pending'` | только `status` (`pending`/`approved`/`rejected`) и `moderatedAt == request.time` | только `rejected` |

Правила не фильтруют выдачу: публичный запрос обязан содержать `where('status', '==', 'approved')`,
иначе Firestore отклонит его целиком. Так устроены все запросы сайта (`reviewsStore.js`).

`isValidReview` пропускает отзыв, только если:

- в документе **нет лишних полей** (`hasOnly`) и есть все обязательные (`hasAll`);
- `name` — строка 2–50 символов, `text` — строка 10–1000 символов;
- `rating` — **целое число** от 1 до 5 (строку `"5"` или `4.5` сервер отклонит);
- `lang` — `ru`, `ky` или `en` (если указан);
- `status` — **обязателен** и равен `pending` (сразу `approved` или `rejected` отправить нельзя);
- поля `moderatedAt` при создании нет — его ставит только администратор при модерации;
- `createdAt == request.time` — дату нельзя подделать.

Почему так безопасно:

- Проверку в браузере можно обойти, отправив запрос напрямую, — поэтому **главная защита в правилах**,
  которые выполняет сервер Firebase. Без правил любой мог бы записать в базу что угодно.
- Никогда не публикуйте правила вида `allow read, write: if true;` (режим «test mode» из Firebase Console):
  с ними любой может стереть или подменить все отзывы и заказы.
- Последний блок `match /{document=**} { allow read, write: if false; }` закрывает всё, что не разрешено явно.

**Модерация и спам.** Новый отзыв не публикуется сразу: сайт показывает только одобренные
(`docs/ADMIN_SETUP.md`, разделы 8–11). Администратор одобряет, отклоняет, возвращает в ожидание и
навсегда удаляет отклонённые отзывы в админ-панели: `/admin/reviews` (раздел 11). Из браузера
отклонённый отзыв может навсегда удалить только администратор; в Console владелец может удалить любой.
В браузере стоит ограничение «не чаще одного отзыва в минуту», но его легко обойти — от массового спама
дополнительно помогут:

- **проверка отзывов через сервер с App Check** — отдельная доработка (сейчас App Check проверяет только
  гостевые заказы на сервере). **Не включайте** в Firebase Console App Check Enforcement для Cloud Firestore
  и Authentication: сайт не отправляет токен App Check в каждом запросе к Firestore, и после включения
  перестанут работать каталог, вход, отзывы и кабинет (см. `docs/LAUNCH_CHECKLIST.md`, шаг 4);
- **отзывы только от вошедших пользователей**: в правилах `request.auth != null`, а ID документа = `uid` —
  тогда один пользователь может оставить один отзыв.

**Проверка после подключения:** откройте `/reviews`, оставьте отзыв → появится сообщение о модерации,
в списке отзыва нет → в админ-панели `/admin/reviews` он на вкладке «Ожидают» → «Одобрить» → обновите
`/reviews` — отзыв в списке. Без риска для рабочих данных то же можно проверить на эмуляторах
(`docs/ADMIN_SETUP.md`, раздел 12).

**Автоматические тесты правил** — `npm run test:rules`: 51 тест на локальном Firebase Emulator
(demo-проект `demo-aroma-donna`, настоящая база не используется) проверяет гостя, покупателя,
анонимного пользователя и администратора для `reviews`, а также что правила `users`, `orders`,
`products`, `admins` и запрет по умолчанию не сломаны. Нужна Java 21+ (например, Eclipse Temurin 21).

### Безопасность

- Файл `.env` указан в `.gitignore` и **не включён в архив** — не отправляйте его другим людям.
- `apiKey` веб-приложения Firebase — это идентификатор проекта, а не секретный пароль; он всё равно
  попадает в браузер. Данные защищает не скрытие ключа, а **правила Firestore** (`firestore.rules`):
  пользователь читает только **свои** заказы; создаёт заказы только сервер (`/api/order`, Firebase Admin SDK),
  а администратор меняет у заказа (обычного и гостевого) только статус. Удалять заказы нельзя.
  Одобренные отзывы читают все, создавать их можно только в строгом формате со `status: 'pending'`;
  менять статус и удалять отклонённые может только администратор (см. выше).
  Эта проверка выполняется **на сервере Firebase**, а не скрытием кнопок в интерфейсе.
- Пароли никогда не сохраняются в `localStorage`.
- Данные банковских карт сайт не запрашивает: оплата только при получении.

> Интеграция с Firebase написана по официальному модульному API (`firebase/auth`, `firebase/firestore`),
> но **не проверялась на реальном проекте Firebase** — ключей для проверки не было. Проверьте её после подключения.

## 9. Форма «Контакты»: EmailJS и Telegram

Форма на странице `/contacts` отправляет каждое сообщение **по двум каналам**:

```
Браузер ──(@emailjs/browser)──────────────► EmailJS ──► ваша почта
Браузер ──POST /api/contact──► серверная функция ──► Telegram Bot API ──► ваш Telegram
                               (api/contact.js, токен только здесь)
```

- **E-mail** отправляется из браузера через официальный SDK `@emailjs/browser`. Public Key EmailJS
  предназначен для браузера и секретом не является.
- **Telegram** — только через серверную функцию. Токен бота даёт полный контроль над ботом,
  поэтому он хранится в переменных окружения сервера и **никогда** не попадает в браузер или GitHub.
- «Спасибо» показывается, **только если оба канала подтвердили доставку**. Если один канал не сработал,
  форма показывает ошибку и сохраняет текст; при повторном нажатии «Отправить» уходит только
  недоставленная часть (без дублей).

### Шаг 1. Настройка EmailJS

1. [dashboard.emailjs.com](https://dashboard.emailjs.com) → **Email Services → Add New Service** →
   подключите свою почту (например Gmail). Скопируйте **Service ID** (вида `service_xxxxxxx`).
2. **Email Templates → Create New Template**. В шаблоне можно использовать переменные:

   | Переменная | Что в ней |
   |---|---|
   | `{{name}}` | Имя посетителя |
   | `{{email}}` | E-mail посетителя |
   | `{{title}}` | Тема (по-русски, например «Вопрос о заказе») |
   | `{{message}}` | Текст сообщения |
   | `{{time}}` | Дата и время отправки |
   | `{{reply_to}}` | E-mail посетителя (для поля Reply-To) |

   Пример: **Subject** — `AROMA DONNA: {{title}} от {{name}}`; **Content** — `{{message}}`;
   **To Email** — ваша почта; **Reply To** — `{{reply_to}}` (тогда «Ответить» в почте пишет посетителю).
   Сохраните и скопируйте **Template ID** (вида `template_xxxxxxx`).
3. **Account → General** → скопируйте **Public Key**.
4. Рекомендуется: **Account → Security** → включите разрешённые домены (localhost и адрес сайта на Vercel)
   — тогда чужие сайты не смогут слать письма от вашего аккаунта.

### Шаг 2. Настройка Telegram-бота

1. Токен бота вы получили от [@BotFather](https://t.me/BotFather) (вида `123456789:AA...`).
   Если токен где-то «засветился» — в BotFather выполните `/revoke` и получите новый.
2. Узнайте свой **chat_id**:
   - откройте своего бота в Telegram и отправьте ему любое сообщение (например `/start`) —
     без этого бот не может писать вам первым;
   - откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` (подставьте токен);
   - в ответе найдите `"chat":{"id":123456789,...}` — это число и есть `TELEGRAM_CHAT_ID`.
   Для группы: добавьте бота в группу, напишите в ней сообщение — id группы будет отрицательным (`-100...`).

### Шаг 3. Переменные окружения

| Переменная | Где взять | Секрет? |
|---|---|---|
| `VITE_EMAILJS_SERVICE_ID` | EmailJS → Email Services | нет |
| `VITE_EMAILJS_TEMPLATE_ID` | EmailJS → Email Templates | нет |
| `VITE_EMAILJS_PUBLIC_KEY` | EmailJS → Account → General | нет (публичный ключ) |
| `TELEGRAM_BOT_TOKEN` | @BotFather | **да** — только сервер |
| `TELEGRAM_CHAT_ID` | `getUpdates` (см. шаг 2) | нет, но не публикуйте |

> **Важно:** Vite передаёт в браузер только переменные с префиксом `VITE_`. Поэтому у Telegram-переменных
> префикса **нет** — никогда не называйте токен `VITE_TELEGRAM_...`.

**Локально:** скопируйте `.env.example` в `.env` (если ещё не сделали), заполните пять значений и
перезапустите `npm run dev`. В режиме разработки `vite.config.js` сам обслуживает `/api/contact` той же
логикой, что и Vercel, поэтому форму можно проверить полностью без публикации.
(`npm run preview` серверную функцию не запускает — там Telegram-канал покажет ошибку.)

**На Vercel:** Project → **Settings → Environment Variables** → добавьте все пять переменных
(окружения Production и Preview) → **Deployments → Redeploy**. Переменные `VITE_*` встраиваются при сборке,
поэтому после их изменения нужна новая сборка.

### Шаг 4. Проверка

1. Откройте `/contacts`, заполните форму, нажмите «Отправить».
2. Должно прийти письмо и сообщение в Telegram, на сайте — «Спасибо за сообщение!».
3. Если видите ошибку — откройте консоль браузера (F12) и логи функции (Vercel → Project → **Logs**):
   - `Отправка сообщений сейчас недоступна` — не заданы переменные (или не было Redeploy);
   - `Telegram ответил ошибкой: 401` — неверный токен; `400 chat not found` — неверный chat_id
     или вы не написали боту `/start`;
   - ошибка EmailJS `400/412` — проверьте Service ID, Template ID, Public Key и подключение почты в EmailJS.

### Защита от спама и ошибок

| Что | Где |
|---|---|
| Проверка полей (имя 2–100, e-mail, тема из списка, сообщение 10–1000 символов) | в браузере **и** на сервере (общий код `src/utils/validation.js`) |
| Лимит: не больше 5 сообщений с одного IP за 10 минут → ответ `429` | серверная функция |
| Лимит EmailJS SDK: не чаще 1 письма в 10 секунд из одного браузера | `limitRate` в `contactService.js` |
| Скрытое поле-ловушка для ботов (honeypot) | форма + сервер |
| Только `POST`, тело ≤ 10 КБ, экранирование HTML в Telegram, тайм-аут 8 с | серверная функция |
| Токен не выводится ни в ответах, ни в логах | серверная функция |

> Лимит частоты хранится в памяти функции. На Vercel может работать несколько экземпляров функции
> одновременно, и память сбрасывается при «холодном» старте — это защита от случайного спама,
> а не строгая гарантия. Для строгого лимита можно подключить общее хранилище (например Upstash Redis)
> и/или reCAPTCHA в настройках EmailJS.

4. **Settings → Environment Variables** → добавьте нужные переменные из `.env`: шесть `VITE_FIREBASE_*` (для Firebase),
   три `VITE_EMAILJS_*` и `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (для формы «Контакты», см. [раздел 9](#9-форма-контакты-emailjs-и-telegram)),
   а для оформления заказов — `FIREBASE_SERVICE_ACCOUNT_B64`, `ORDER_HMAC_SECRET` и `VITE_RECAPTCHA_SITE_KEY`.
   Полный порядок действий (Firebase Console, App Check, правила, проверка) — в [docs/LAUNCH_CHECKLIST.md](docs/LAUNCH_CHECKLIST.md).
5. **Deploy.**
6. Если используете Firebase: в Firebase Console → Authentication → **Settings → Authorized domains**
   добавьте адрес сайта на Vercel (`aroma-donna.vercel.app` и т.п.).

## 12. Подготовка к защите проекта

### Что такое React и зачем он нужен?

React — JavaScript-библиотека для создания интерфейсов из **компонентов**. Мы описываем, *как*
должен выглядеть интерфейс при данных, а React сам обновляет только изменившиеся части страницы.
Здесь это важно: при добавлении товара меняются значок корзины, кнопка и уведомление — без перезагрузки.

### Что такое компонент?

Функция, которая возвращает разметку (JSX). Например, `ProductCard` получает товар и рисует карточку.
Одну карточку мы используем 24 раза в каталоге, на главной и в похожих товарах — не копируя код.

### Чем отличаются `main.jsx` и `App.jsx`?

- **`main.jsx`** — точка входа. Находит `<div id="root">` в `index.html`, создаёт React-приложение и
  оборачивает его в провайдеры: `Provider` (Redux), `BrowserRouter` (маршруты), `ThemeProvider` (тема).
  Здесь же подключаются стили и переводы.
- **`App.jsx`** — корневой компонент: описывает **маршруты** (какая страница по какому адресу) и
  при запуске загружает товары и проверяет вошедшего пользователя.

### Что такое JSX?

Синтаксис, похожий на HTML, внутри JavaScript: `<h1>{product.name}</h1>`. В фигурных скобках — любое
JS-выражение. Отличия от HTML: `className` вместо `class`, `htmlFor` вместо `for`. Vite превращает JSX в обычный JavaScript.

### Что такое props и state?

- **props** — данные, которые компонент **получает** от родителя (только для чтения).
  Пример: `<ProductCard product={product} />`.
- **state** — данные, которые компонент **хранит и меняет сам**. Пример: в `ProductInfo`
  `const [quantity, setQuantity] = useState(1)` — выбранное количество. При изменении state
  компонент перерисовывается.

### Что такое React Hooks? Для чего useState, useEffect, useRef?

Хуки — функции, которые дают компонентам возможности React. Вызываются только на верхнем уровне компонента.

- **`useState`** — хранит изменяемое значение. Пример: шаг теста в `FragranceQuiz`.
- **`useEffect`** — выполняет действие **после отрисовки**: загрузка, подписки, таймеры.
  Пример: `AccountPage` загружает заказы; `Notification` ставит таймер автозакрытия и
  **очищает** его в функции возврата.
- **`useRef`** — «коробка» для значения, изменение которого **не** вызывает перерисовку,
  или ссылка на DOM-элемент. Пример: в `LanguageSwitcher` ref на меню, чтобы закрыть его по клику
  снаружи; в `CheckoutPage` — флаг «заказ уже отправлен».
- **`useMemo`** — запоминает результат вычисления. Пример: в каталоге список пересчитывается только
  при изменении товаров или фильтров.
- **`useCallback`** — запоминает функцию (например, `closeMenu` в `Header`), чтобы эффекты не перезапускались.
- **Собственные хуки:** `useShopActions` (в корзину/избранное + уведомление), `useCatalogFilters`
  (фильтры в адресной строке), `useTheme`, `useClickOutside`, `useDocumentTitle`.

### Что такое React Router?

Библиотека маршрутизации: показывает нужную страницу по адресу без перезагрузки. В `App.jsx`
описаны `<Route path="catalog" element={<CatalogPage />} />`. `MainLayout` содержит шапку и подвал, а
`<Outlet />` — место для текущей страницы. `useParams` достаёт `:id` из `/product/rose-poudree`,
`useNavigate` переходит программно (после оформления заказа), `useSearchParams` читает фильтры из `?…`,
`path="*"` — страница 404.

### Для чего Redux Toolkit?

Хранит **общие** данные, нужные многим компонентам. Корзина нужна шапке (значок), карточкам,
корзине, оформлению — поэтому она в Redux. Без Redux пришлось бы передавать данные через props по
многим уровням. Redux Toolkit упрощает Redux: `createSlice` создаёт actions и reducers сразу,
`createAsyncThunk` — асинхронные действия с состояниями `pending/fulfilled/rejected`.

### Как работает корзина?

1. Кнопка «В корзину» вызывает `addProductToCart` из хука `useShopActions`.
2. Он отправляет действие `addToCart({ id, volume, quantity })` и уведомление.
3. Reducer в `cartSlice` ищет позицию с таким же товаром **и объёмом**: если есть — увеличивает
   количество (максимум 10), если нет — добавляет новую.
4. В состоянии хранятся только `id`, объём и количество. Название и цену селектор `selectCartItems`
   берёт из каталога — данные не дублируются.
5. `selectCartTotals` считает сумму, скидку по промокоду и итог; шапка показывает `selectCartCount`.

### Как сохраняются данные в localStorage?

В `store/store.js`: при запуске корзина и избранное **читаются** из `localStorage` (`preloadedState`),
а `store.subscribe` при каждом изменении **записывает** их обратно (только если они изменились).
Язык сохраняется в `i18n.js`, тема — в `useTheme.jsx`. Все обращения обёрнуты в `try/catch`
(`utils/storage.js`), чтобы приложение не падало, если `localStorage` недоступен.

### Как устроены поиск, фильтры и сортировка?

Фильтры хранятся в адресе (`useCatalogFilters`), поэтому ссылку с фильтрами можно отправить и работает
кнопка «Назад». Сама обработка — чистые функции в `utils/filterProducts.js`: `filterProducts` проверяет
каждое условие (поиск по названию/бренду без учёта регистра, категория, бренд, семейство, цена,
наличие), `sortProducts` сортирует **копию** массива. В `CatalogPage` это обёрнуто в `useMemo`.

### Как работает тест подбора аромата?

Это **не искусственный интеллект**, а система баллов (`utils/quizMatcher.js`):
совпадение семейства +40, каждая любимая нота +10 (до +30), интенсивность +15 (соседняя +5),
категория +10 (унисекс +5, другая −10), цена в бюджете +15 (иначе −20), нет в наличии −15.
Товары сортируются по баллам, показываются 4 лучших; процент = баллы / максимум (110).

### Как устроены мультиязычность и темы?

- **Языки:** `i18next` хранит переводы из `locales/ru|ky|en/translation.json`. В компоненте:
  `const { t } = useTranslation()` и `t('cart.title')`. Множественное число (`1 товар / 2 товара / 5 товаров`)
  — суффиксы `_one/_few/_many`. Ошибки форм и уведомления хранятся как **ключи**, поэтому
  показываются на текущем языке. Пользовательский ввод не переводится.
- **Темы:** все цвета — CSS-переменные в `styles/variables.css`. Для тёмной темы переопределяются
  только значения переменных под `[data-theme='dark']`. `ThemeProvider` ставит атрибут на `<html>`,
  сохраняет выбор и при первом визите берёт системную настройку. Маленький скрипт в `index.html`
  применяет тему **до** загрузки React, чтобы не было вспышки светлой темы.

### Для чего Firebase?

Облачный сервис от Google без своего сервера: **Authentication** (регистрация, вход, хранение
паролей) и **Firestore** (база данных для профиля и заказов). Код обращения к нему спрятан в
`services/`, поэтому остальное приложение не знает, работает ли оно с Firebase или с демо-режимом.

### Что демонстрационное, а что настоящее?

| Настоящее (работает реально) | Демонстрационное |
|---|---|
| Интерфейс, маршруты, корзина, расчёты, фильтры, квиз, языки, темы, сохранение в браузере | Товары, бренды, рейтинги, наличие (вымышленные) |
| Регистрация/вход/заказы через Firebase — **после подключения ключей** | Вход и заказы без Firebase (только в браузере, пароль не проверяется) |
| Проверка всех форм; форма обратной связи — после подключения EmailJS и Telegram | Промокоды (не реальные акции), оплата (её нет) |

### Возможные вопросы преподавателя

1. **Почему корзина в Redux, а количество на странице товара — в useState?** Корзина нужна многим компонентам; выбранное количество — только одному.
2. **Что будет, если обновить страницу?** Корзина, избранное, язык и тема восстановятся из `localStorage`.
3. **Как связаны кнопки «сердечко» в разных местах?** Все читают один список `favorites.ids` из Redux.
4. **Зачем `key` в списках?** Чтобы React понимал, какой элемент изменился. Мы используем `product.id`, а в `ProductPage` `key={product.id}` у `ProductInfo` сбрасывает выбранный объём при переходе к другому товару.
5. **Что такое createAsyncThunk?** Асинхронное действие: `fetchProducts` проходит `pending` → `fulfilled`/`rejected`, и интерфейс показывает загрузку или ошибку.
6. **Как защищён личный кабинет?** В интерфейсе — `ProtectedRoute` (перенаправляет на вход). Сами данные защищают правила Firestore на сервере.
7. **Почему пароль не хранится в localStorage?** Это небезопасно: localStorage читается любым скриптом на странице.
8. **Как работает 404?** Маршрут `path="*"` срабатывает, если ни один другой адрес не подошёл.
9. **Почему стили на CSS, а не Tailwind?** Одна система стилизации, темы через переменные, проще объяснить.
10. **Что делает `vercel.json`?** Направляет все адреса на `index.html`, чтобы маршрутизацией занимался React Router.
11. **Как считается скидка?** `utils/promo.js`: процент от суммы или фиксированная сумма, если заказ не меньше минимума.
12. **Сколько компонентов?** 58 компонентов интерфейса + 15 страниц + макет + App + ThemeProvider.
